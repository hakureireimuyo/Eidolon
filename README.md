# Eidolon

> **可演化的叙事 / 模拟运行时(Narrative / Simulation Runtime)。**
> 一张图就是一个世界:节点因事件演化,数据沿连线因果传播,信号决定网络的通断。
> LLM 是世界的语言接口,不是大脑。

## 这个项目要做什么

Eidolon 要构建的,是一个**持续运行、维护内部状态、按环境变化采取行动的状态系统**
——一个"叙事游戏引擎"的运行时核心:世界由节点与连线构成,角色、人格、
记忆、经济、剧情规则都是同一张图中的实体;系统决定"发生什么",
模型负责"描述发生过程"。

类比:物理引擎决定物体怎么动,渲染引擎决定看起来怎么样——Eidolon 决定
世界怎么演化,LLM 负责把演化用语言表达出来。

## 解决什么问题

- **时间模型的错位**:聊天框架的核心抽象是"一次请求—响应",而叙事 / 模拟
  需要的是持续运行的状态系统。角色不是等消息的接口,是**按世界状态行动
  的实体**——等待不是时间,是触发条件未满足;
- **LLM 被误当大脑**:剧情走向、世界演化不该由一次模型调用决定。状态由
  系统维护、能力是状态转换器、模型是可替换的执行节点——三者完全解耦;
- **固定剧情树的死路**:剧情不是一棵预先写好的树,而是**事件与规则驱动
  的动态世界**。策略(对话策略、角色行为、代理逻辑)不是特权代码,而是
  一张用户可编辑、可快照、可复现的**图**;
- **"理解不了就拒绝"**:数据容器不拒绝不理解的模块,运行时也不拒绝尚未
  实现的扩展——三件同构的事(未知的数据如何存在、未知的能力如何参与
  运行、Agent 如何解释数据),共享同一条哲学:**允许未知生长**;
- **不可复现的调试地狱**:同一张图、同一输入序列 → 同一结果。世界的每次
  变化都有因果记录(run/seq 时间线),读档续跑与从未中断完全一致。

## 设计思想

1. **图是世界运行的蓝图**:节点 = 状态机,连线 = 数据与信号的路由;注入 →
   因果传播 → 静止,每个 epoch 就是一个可解释的因果闭包;
2. **内核不知道领域**:LLM、Context、Agent、Tool 都不是运行时的特殊概念,
   只是图中的某种节点。内核只认节点协议(声明、执行、产出、异步、
   持久化),实现内部是什么是节点自己的问题;
3. **能力与包装分离**:能力库(模型调用、媒体处理……)零图概念、零协议
   依赖;内核的封装层把能力包装成节点——"execute() 内部是 OpenAI 还是
   本地模型"与图无关;
4. **异步 = 宿主完成注入**:节点不产出即等待,外部结果到达后由宿主注入
   完成事件。内核没有 pending 队列——时钟、网络、用户点击、LLM 响应
   都是同一类东西:改变某个端口状态的外部事件。

## 架构

```
协议层 format        资产类型层 asset-types
        │                    │
        └────────┬───────────┘
                 ↓
              内核 kernel ←── 能力库 capabilities
                 │
        ┌────────┴────────┐
        ↓                 ↓
    运行时 runtime      编辑器 editor
```

每层是独立仓库,单向依赖,经 rev 传播链联动;目录树即架构。分层原则:
**稳定进核心,不稳定成扩展**——协议层与内核是最稳定的两层,领域知识与
具体能力分别落在资产类型层与能力库,由宿主组装成完整世界。
