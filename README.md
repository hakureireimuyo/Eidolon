# Eidolon

> **图是世界运行的蓝图。** 一个事件驱动的图运行时生态:世界由节点与连线构成,
> 节点因事件执行、数据沿连线因果传播、信号决定网络的通断——所有数字实体
> (角色、NPC、代理、流程)都是同一张图,由同一个内核执行。

## 核心思想

- **世界 = 图,节点 = 状态机**:宿主注入事件,内核从受影响节点出发按数据流
  因果序传播,队列排空即静止。等待不是时间,是触发条件未满足;时钟、网络、
  用户、LLM 都是同一种东西——**改变某个端口状态的外部事件**;
- **内核不知道领域**:LLM、Context、Agent、Tool 都不是运行时的特殊概念,
  它们只是图中的某种节点。内核只认节点协议(`node-protocol`):声明、
  执行、产出、异步、持久化——实现内部是什么,是节点自己的问题;
- **策略成为图**:一个"带上下文的 LLM 代理" = 一组节点 + 一组连线 + 一组
  状态,不是一段特权代码。所有策略都是用户可编辑、可快照、可复现的图;
- **确定性可复现**:同一张图、同一输入序列 → 同一结果(数据流因果序 +
  每节点独立随机流 + run/seq 因果时间线)。

## 架构分层

目录树即架构。每一层是独立仓库,单向依赖,经 rev 传播链联动:

```
协议层 (format)        数据容器:资产如何序列化、索引、校验、迁移
                        ↑ 它不知道"内容语义",只知道"有数据块和类型标签"
资产类型层 (asset-types)  在协议层之上定义数据 Schema(身份、工程……)
内核 (kernel)          图模型 + 执行模型 + 节点协议(稳定 ABI)+ 内置原语
                        ↑ 所有节点共同遵守的执行基础,唯一的稳定核心
能力库 (capabilities)  纯能力:模型调用、媒体处理……零图概念、零协议依赖
                        ↑ 内核的封装层引用能力库,把能力包装成节点
宿主 (runtime / editor) 组装世界、驱动会话、提供界面——消费一切的应用层
```

分层的关键性质:

- **能力与包装分离**:能力库完全不认识图(谁都能用),内核封装层把能力
  包装成节点(协议的唯一实现面);
- **节点协议 = 稳定 ABI**:实现协议 → 注册类型 → 内核即可执行。节点可以
  居住在内核封装层,也可以来自独立节点包——注册方式完全相同;
- **异步 = 宿主完成注入**:节点不产出即等待,外部结果到达后由宿主注入
  完成事件(与用户点击输入同构)。内核没有 pending 队列,超时/重试是
  封装层与能力库的业务。

## 贯穿全局的设计原则

1. **规则与事实分离**:节点类型是声明式资产(端口/状态/配置/组),实现是
   代码;世界快照是事实,资产是规则——编辑事务天然位于两次运行之间;
2. **条目级版本**:图资产版本 = 内核格式版本;元数据/资源各自独立版本,
   损坏可重建、互不牵制;
3. **快照即世界事实**:状态字段表、输入缓冲、信号电平、随机流——读档续跑
   与从未中断完全一致;
4. **单写者**:节点状态只能被自己的执行写,无并发写、无事务冲突;
5. **原子写与提交点**:工程落盘永远"要么完整旧版本,要么完整新版本"。

## 工程约定

- **一仓库一层级**:每层独立 git 仓库,主仓以 submodule 收编;目录树与
  架构分层一一对应;
- **git 源 + pin rev**:跨仓库依赖一律 `git + rev` 声明,monorepo 检出与
  独立 clone 一致,无路径耦合;
- **rev 传播链**(`scripts/propagate-rev.sh`):底层修复后一条命令穿透全部
  消费仓(pin 更新 → lock → 提交 → 推送 → 顶层指针),幂等可重跑;
- **测试随协议走**:内核测试锁定执行语义与节点协议 ABI,任何破坏协议的
  改动在协议测试处必红。
