# eidolon-host — Eidolon 组合根

> **Host 是 Eidolon 第一个真正意义上的生态边界。**

- **Kernel** 定义计算模型(NodeType/Graph/Event/State/Execution/AssetRef/Capability 边界)
- **DSL** 定义节点语言
- **Host** 定义如何把外部世界装配进这个计算模型

本目录是组合根所在;根目录 `editor/` 与 `runtime/` 下的兄弟项目(独立 git 仓库)
与 Kernel、DSL 等平级分类,逻辑上以 git 源 + pin rev 的包依赖方式被宿主引用,
可独立演化和发布。

```text
                 Host
        ┌──────────┼──────────┐
        ↓          ↓          ↓
     Editor     Runtime    Project
        │          │
        └────┬─────┘
             ↓
      Common Host Services
       ├── Plugins
       ├── Assets
       ├── DSL
       └── Registry
             ↓
          Kernel
```

## 图中名词的定义

| 名词 | 定义 |
|------|------|
| **Editor** | 装配对象:项目创作环境(studio 使用者界面层,整合 graph-editor 图编辑服务)。回答"这个项目是什么" |
| **Runtime** | 装配对象:运行形态(当前 Web 形态的运行入口)。提供 I/O 能力,不规定 I/O 语义与表现 |
| **Project** | 装配对象(数据):图工程——目录工程 ↔ 标准包双向无损互转;图资产 + 编辑器元数据 + 全局变量初值 + 资源。Host 装载的对象 |
| **Plugins** | 宿主服务:外部节点包 / 能力包的发现、加载与生命周期管理(内核的"包概念"与外部节点 ABI 的装配面) |
| **Assets** | 宿主服务:真实资产系统装配——按已裁定的资产协议,把能力(如 LLM 能力库)以 Capability 绑定到节点声明的 AssetIn 槽位 |
| **DSL** | 宿主服务:节点定义语言的宿主侧承载——"定义 → 编译 → 注册"的装配路径(DSL 语义本身冻结于内核仓,宿主不重新定义节点语言) |
| **Registry** | 宿主服务:节点注册表——收集全部 NodeType 注册进内核,使图资产中的 type_name 可实例化(内核不内置任何具体节点) |
| **Kernel** | 计算模型本体(以冻结语义基准为 Oracle)。零第三方依赖,不认识具体节点 |

## "宿主"一词的三义与裁定

| 用法 | 含义 | 裁定 |
|------|------|------|
| Host(组合根) | 本目录;装配层 | ✅ 本文档主体 |
| 宿主侧能力 | 内核明确排除、由驱动内核的一方承担的能力(实时调度、并发多实例、节点注册、注入节奏) | ✅ 保留;是 Host 职责的内容清单 |
| 宿主层(旧义) | 早期文档中 Runtime 的定位 | ❌ 已被取代;Runtime 降格为装配对象,职责不变 |
